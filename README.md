<h2>Розподілена вебсистема асинхронного обернення матриць високої розмірності</h2>

Масштабоване вебзастосування для виконання трудомістких матричних обчислень ($A^{-1}$ методом Гауса–Жордана з вибором головного елемента, складність $O(N^3)$) із балансуванням навантаження **Nginx Round Robin**, чергою задач **Celery + Redis**, горизонтальним авто-масштабуванням воркерів та панеллю моніторингу адміністратора.

---

<h3>Технологічний стек</h3>

* **Backend:** Python 3.11, FastAPI, Pydantic v2
* **База даних та ORM:** PostgreSQL 15, SQLModel (SQLAlchemy 2.0) + Alembic
* **Фонові задачі та черги:** Celery 5 + Redis 7
* **Балансування навантаження та безпека:** Nginx 1.27 (Round Robin Load Balancer + HTTPS/TLS із самопідписаним сертифікатом), JWT (OAuth2 + `bcrypt`)
* **Контейнеризація та автоскейлінг:** Docker, Docker Compose, Docker SDK (`psutil`, `docker`)

---

<h3>Реалізація вимог завдання (основні + додаткові бали)</h3>

1. **Обмеження максимальної трудомісткості задачі:**
   * Розмірність квадратної матриці суворо обмежена діапазоном $2 \le N \le 600$ як на клієнті (JavaScript), так і на бекенді (`TaskCreateRequest`). При перевищенні повертається помилка `422 Unprocessable Entity`.
   * На рівні Celery встановлено жорсткі часові ліміти: `TASK_SOFT_TIME_LIMIT_SEC = 60` та `TASK_HARD_TIME_LIMIT_SEC = 70`. При перевищенні ліміту задача переходить у стан `TIMEOUT`.
2. **Інформування клієнта про хід виконання (відсоток та етап):**
   * Під час прямого та зворотного ходу методу Гауса–Жордана воркер оновлює прогрес (`0..100%`) і текстовий опис поточного рядка (`Елімінація Гауса-Жордана: оброблено рядок k з N`).
3. **Історія задач, перегляд стану, скасування та квоти:**
   * Збереження історії обчислень, часу виконання та норми нев'язки $\|A \cdot A^{-1} - I\|_\infty$ у PostgreSQL.
   * Миттєве скасування задачі (`POST /api/tasks/{id}/cancel`) через прапорець у Redis та `celery.control.revoke(..., terminate=True)`.
   * Обмеження на кількість задач: до **2** одночасно активних задач та до **20** збережених задач в історії на користувача.
4. **Авторизація клієнта + HTTPS (+бали):**
   * JWT-авторизація з ролями `user` та `admin`.
   * Nginx автоматично генерує TLS-сертифікат і обслуговує трафік по `HTTPS (443)` із автоматичним перенаправленням `HTTP (80) -> HTTPS (443)`.
5. **Балансування навантаження для 2+ серверів (основна вимога):**
   * Nginx розподіляє вхідні запити за алгоритмом **Round Robin** між двома контейнерами застосувань (`backend-1` та `backend-2`).
   * Кожен бекенд повертає HTTP-заголовок `X-Served-By: <hostname>`, який відображається в реальному часі у верхній панелі веб-інтерфейсу.
6. **Черга задач та розрахунок орієнтовного часу очікування ETA (+бали):**
   * При завантаженості всіх воркерів (`worker_prefetch_multiplier=1`) нові запити стають у чергу зі статусом `QUEUED`.
   * Система розраховує позицію в черзі та орієнтовний час очікування в секундах на основі кубічної складності $O(N^3)$, поточного відсотка виконання активних задач та фактичного коефіцієнта швидкодії воркерів у Redis.
7. **Горизонтальне розширення з обмеженням максимальної кількості серверів (+бали):**
   * Сервіс `autoscaler` моніторить чергу задач і автоматично масштабує кількість активних воркерів у межах `MIN_WORKERS = 2` .. `MAX_WORKERS = 4`.
8. **Панель адміністратора для моніторингу процесів та навантаження (+бали):**
   * Дашборд адміністратора відображає навантаження CPU та RAM, список вузлів `backend-1` / `backend-2`, стан воркерів Celery (`IDLE` / `BUSY`), керування автоскейлером та глобальну таблицю всіх задач користувачів із можливістю примусової зупинки.

<h3>Швидкий запуск через Docker Compose</h3>

```bash
docker compose up --build -d
```

Після запуску сервіси доступні за адресами:
* **HTTPS Веб-інтерфейс та Load Balancer:** `https://localhost` (HTTP `http://localhost` автоматично перенаправляє на HTTPS)
* **Swagger UI (OpenAPI документація):** `https://localhost/docs`
* **Обліковий запис адміністратора за замовчуванням:** логін `admin`, пароль `admin123`

---

<h3>Локальний запуск тестів</h3>

```bash
pytest -v
```

Перевірка роботи кластера та балансування скриптом:

```bash
python scripts/verify_cluster.py https://localhost
```

<h3>Основні ендпоінти REST API</h3>

| Метод | Шлях | Опис |
|---|---|---|
| `GET` | `/api/health` | Перевірка стану БД, Redis та поточного інстансу бекенду |
| `GET` | `/api/cluster/node` | Інформація про вузол кластера, що обробив запит (`X-Served-By`) |
| `POST` | `/api/auth/register` | Реєстрація нового користувача |
| `POST` | `/api/auth/login` | Авторизація та отримання JWT-токена |
| `GET` | `/api/auth/me` | Профіль поточного користувача та ліміти |
| `POST` | `/api/tasks` | Запуск нової задачі обернення матриці $A^{-1}$ |
| `GET` | `/api/tasks` | Історія задач користувача та активні квоти |
| `GET` | `/api/tasks/{id}` | Поточний статус, `%` прогресу, етап, позиція в черзі та ETA |
| `GET` | `/api/tasks/{id}/result` | Отримання обчисленої оберненої матриці $A^{-1}$ та норми нев'язки |
| `POST` | `/api/tasks/{id}/cancel` | Скасування виконання активної або очікуючої задачі |
| `DELETE` | `/api/tasks/{id}` | Видалення завершеної задачі з історії |
| `GET` | `/api/admin/overview` | Моніторинг CPU/RAM, стану вузлів кластера та автоскейлера |
| `GET` | `/api/admin/tasks` | Перегляд усіх задач усіх користувачів |
| `POST` | `/api/admin/workers/scale` | Горизонтальне масштабування серверів воркерів (ліміт до 4) |
| `POST` | `/api/admin/tasks/{id}/cancel` | Примусова зупинка задачі адміністратором |
